# Iconography

<!-- iconography-contract: sizes=xs,sm,md,lg,xl;default=sm;library=Lucide;stroke=2 -->

> Los iconos apoyan la comprensión.
> Nunca reemplazan el texto. Nunca decoran.

---

## Iconography Intent

Esta sección explica **por qué** existe Iconography — no solo qué tamaños usar.

### Los iconos son apoyo cognitivo, no sustituto de texto

En una plataforma clínica, "Completed" con un check puede reforzar un estado — pero un check solo sin texto falla para screen readers, usuarios con daltonismo, y scanning rápido en tablas densas. Los iconos **refuerzan** significado ya presente en texto o color semántico.

**Implicación:** Icono + texto en acciones. Icono solo solo con `aria-label` en controles icon-only. Nunca icono solo para estado clínico crítico.

### Menos iconos, usados consistentemente

Cada icono distinto en una toolbar añade carga de parsing. Medmo prefiere **icon-sm (16px)** en el 90% de casos, Lucide, stroke 2, `currentColor` — para que el usuario no re-aprenda vocabulario visual en cada pantalla.

**Implicación:** Cinco tamaños. Un stroke. Una biblioteca. Sin excepciones locales.

### Claridad clínica sobre expresividad

No ilustraciones, no iconos "friendly", no gradientes en glyphs. Linear/GitHub/Stripe — funcional, preciso, silencioso.

**Implicación:** Casos donde **no** usar iconos documentados explícitamente.

### Grid base 24px — no "default 24px everywhere"

24px (`icon-lg`) es la **referencia de grid** alineada con spacing (space-page, space-dialog). El default de producto es **16px** (`icon-sm`). `icon-xl` es raro — empty state focal, una vez por vista.

---

## Filosofía

| Principio | Aplicación |
|-----------|------------|
| **Support comprehension** | Icon reinforces text/state |
| **Never replace text** | Clinical labels stay textual |
| **Never decorate** | No icons "for beauty" |
| **Lucide only** | No mixed libraries |
| **currentColor** | Inherits semantic text/icon color |
| **icon-sm default** | 16px unless context says xs/md/lg/xl |
| **One stroke (2)** | No thin decorative strokes |
| **Spacing from Spacing** | gap via space-inline-* |

## Arquitectura

```
scale.ts (primitive dimensions)
        ↓
semantics.ts (xs/sm/md/lg/xl + default + library + stroke + contexts)
        ↓
contract.ts + tooling.ts + iconography.css + documentation
        ↓
Components: width/height var(--icon-sm), strokeWidth 2, color currentColor
```

```
Context (documented, not extra tokens)     Size        Gap (Spacing)
──────────────────────────────────────     ────        ─────────────
button                                     icon-sm     space-button-icon-gap (6px)
input prefix/suffix                        icon-sm     space-inline-xs (4px)
table row action                           icon-sm     space-inline-xs
empty-state focal                          icon-lg     —
header action                              icon-sm     space-inline-sm
```

| Grid base | 24px (`icon-lg`) | Empty states y elementos standalone |

## Tamaños permitidos (API pública)

La matriz ejecutable no se duplica en MDX. `foundations/iconography/scale.ts`
define las dimensiones primitivas y `foundations/iconography/semantics.ts`
asigna los cinco roles públicos (`icon-xs` a `icon-xl`). La documentación viva
renderiza esa estructura directamente desde `@medmo/tokens/tooling`.

```css
width: var(--icon-sm);
height: var(--icon-sm);
```

`icon-sm` es el default. `icon-xs` queda reservado para metadata densa y badges;
`icon-xl` es un focal feature icon de uso excepcional.

---

## Stroke

| Token | Valor |
|-------|-------|
| `icon-stroke` | 2 |

Lucide: `strokeWidth={2}`. Universal — sin excepciones.

**Rechazado:** stroke 1.5 (decorativo), stroke 2.5+ (ruido visual).

---

## currentColor

Regla general: el icono hereda el color del texto/contenedor padre.

```tsx
/* Lucide — color inherits via currentColor by default when using className text-* */
<SearchIcon className="text-[inherit]" strokeWidth={2} />
```

En CSS/SVG: `stroke: currentColor; fill: none` (Lucide outline icons).

**No hardcodear** `#242F50` en SVG de icono — usar tokens de color del padre (`color-text-primary`, `color-action-primary-text`, etc.).

---

## Espaciado icono + texto

No duplicamos gap en Iconography — usamos **Spacing**:

| Contexto | Gap token | Valor |
|----------|-----------|-------|
| Button icon + label | `space-button-icon-gap` | 6px |
| Input icon + text | `space-inline-xs` | 4px |
| Table cell icon + label | `space-inline-xs` | 4px |
| Toolbar actions | `space-inline-md` | 12px (between buttons, not icon-text) |

```css
gap: var(--space-button-icon-gap); /* button with icon */
```

## Uso por contexto

### Botones

- Tamaño: `icon-sm` (default)
- Gap a label: `space-button-icon-gap`
- Icon-only: **obligatorio** `aria-label` descriptivo
- Stroke: 2
- No usar `icon-lg` en button default

### Inputs

- Prefix/suffix (search, password toggle): `icon-sm`
- Gap: `space-inline-xs`
- No reemplazar `<Label>` con icono
- Chevron Select: `icon-sm`, mismo stroke

### Tablas

- Row actions: `icon-sm` — paired with text tooltip or aria-label
- Sort indicator: `icon-sm`
- Status: **icon + text + color** — never icon-only for clinical status
- No columna decorativa de iconos
- No `icon-xl` en filas repetidas

### Empty states

- Focal icon: `icon-lg` default, `icon-xl` solo si es el único elemento visual grande
- Una vez por vista — no repetir xl en dashboard tiles

## Accesibilidad

| Regla | Implementación |
|-------|----------------|
| Icon-only button | `aria-label` obligatorio |
| Decorative icon | `aria-hidden="true"` |
| Functional icon | Texto visible adyacente o aria-label |
| Estado clínico | Icon + text + color token — never color/icon alone |
| Touch target | Icon-only button usa Button hit area (44px mobile) — el hit area no depende del tamaño visual |
| Contraste | currentColor sobre fondo — verificar par en Colors |

---

## Cuándo NO utilizar iconos

- Etiquetas de campos clínicos críticos (medicación, diagnóstico)
- Columnas de tabla donde texto + color bastan
- Cada ítem de menú "para variedad visual"
- Duplicar significado ya claro en heading
- Marketing, wellness, celebración
- Botones de acción destructiva **sin** texto confirmatorio (icon + label required)

## Do / Don't

### DO

| Escenario | Patrón |
|-----------|--------|
| Save button | `[SaveIcon sm] + "Guardar"` + button icon gap |
| Search input | SearchIcon sm prefix + xs gap |
| Error state | AlertCircle sm + error text + color-error-text |
| Icon-only close | X sm + `aria-label="Cerrar"` |
| Empty list | Inbox lg + title + description (text) |

### DON'T

| Escenario | Por qué |
|-----------|---------|
| `[✓]` solo para "Completed" en tabla clínica | Screen reader, daltonismo |
| Heroicon mezclado con Lucide | Inconsistencia |
| `strokeWidth={1.5}` en todo | Rechazado — visibility |
| Icon en cada column header sin valor | Ruido visual |
| icon-xl en 20 filas de tabla | Fatiga, decoración |
| `#3B82F6` hardcoded en SVG | Usar currentColor + tokens |

## Biblioteca oficial

**Lucide** (`lucide-react`) — única fuente permitida.

- Consistent stroke geometry
- Ya instalado en el proyecto
- No Heroicons, Font Awesome, SVG custom sets sin aprobación DS

Constante canónica: `foundations/iconography/semantics.ts` → `iconLibrary`

---

## Reglas de uso

### DO

- `var(--icon-sm)` + `var(--icon-stroke)` + currentColor
- Context mappings en `semantics.ts` para button/input/table
- Preguntar token creation principle antes de nuevo tamaño

### DON'T

- `size-4`, `w-4 h-4` en código fuente de primitivos
- Nueva biblioteca de iconos
- Icon como único indicador de urgencia clínica

## Revisión crítica de arquitectura

### ¿Más tamaños?

| Propuesta | Veredicto |
|-----------|-----------|
| icon-xs | **Aprobado solo para metadata densa y badges** |
| Cinco roles semánticos | **Aprobado** — sm cubre el default y xl queda excepcional |
| Per-component sizes | **Rechazado** — use context mapping |

### ¿Más strokes?

| Propuesta | Veredicto |
|-----------|-----------|
| stroke 1.5 thin | **Rechazado** — decorativo, peor legibilidad |
| stroke 2.5 bold | **Rechazado** — ruido visual |
| **Solo stroke 2** | **Aprobado** — Lucide default, clínico |

### ¿Context tokens en CSS?

**Rechazado** — context (button/input/table) es documentación + `semantics.ts`, no `--icon-button-size`. Evita proliferación; size + spacing tokens bastan.

### ¿Gap tokens en Iconography?

**Rechazado** — `space-inline-*` ya existe. Menos tokens, más intención.

**Conclusión:** API = 5 sizes + 1 stroke + `--icon-size` apuntando a `icon-sm`. Las definiciones ejecutables viven en `scale.ts` y `semantics.ts`.
